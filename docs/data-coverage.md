# 数据覆盖与更新时间

报告和 Explore 都说明当前使用的年份、摘要覆盖限制以及数据抓取时间。报告生成日期单独保留。

## 时间从哪里来

成功执行 CLI 或网页抓取后，程序在写入语料时保存 `<文件名>.jsonl.meta.json`，包含 UTC 抓取完成时间、记录数和语料 SHA-256。报告读取时必须校验文件内容。

- 历史文件没有抓取记录：显示 `Data fetched: unknown`。
- 元数据格式错误：显示未知，并说明记录无效。
- 语料内容改变，校验不再匹配：显示未知，并说明语料已改变。
- 复制原始文件和配套元数据：保留原来的抓取时间。
- 重新生成报告、改变文件修改时间：不会更新抓取时间。
- 抓取请求失败：不替换原有语料或抓取记录。

这次没有为现有 19 个历史语料推测时间，也没有为了补一个日期重新请求全部数据。将来通过项目的抓取入口更新时，会自动获得可验证的时间记录。

## 为什么默认不包含某些年份

默认分析最多十个日历年，网页也可选择五年。统一的选择函数同时产生年份和解释：

1. 不使用当前和未来年份，避免把尚在收录中的记录直接当成完整年度。
2. 末年记录少于此前最多三个已观测年份记录数中位数的 20% 时，跳过该年，并显示实际数量和参考中位数。
3. 平时摘要覆盖中位数至少 60%，但末年摘要覆盖不足 50% 时，跳过该年，并显示覆盖比例。

第二、三条逐年向前检查，保留至少一个过去的已观测年份。没有任何过去年份时，显示暂定范围和不完整提示。长期缺少摘要的会议保留历史年份，不因第三条而删去它们。

All、Custom 和 CLI 的 `--years` 可以覆盖默认选择。页面仍说明默认排除依据，并提示所选最新年份可能不完整。这些规则是保守启发式判断，不能证明某年收录完整。

## 如何说明数据缺口

摘要覆盖比例的分母始终是该年本地收录的记录数，不能把它解释成会议论文的收录率。

- 已选年份摘要覆盖低于 90%：列出具体年份和比例，说明摘要可用性变化可能影响短语趋势。例如 GLOBECOM 2025 为 85.2%。
- 整个范围摘要覆盖低于 60%：报告短语趋势只使用标题，并提醒可能遗漏标题之外的研究内容；主题分析仍使用已有标题和摘要。Explore 的关键词模式仍由用户选择。
- 范围内没有记录的年份：覆盖表显示 `No cached records`，摘要比例显示 `—`，不伪造 0% 覆盖率。这可能是会议停办、收录缺口或查询遗漏，不能直接解释成研究产出为零。

覆盖表与说明保留证据；没有添加“数据完整”的认证标签。会议来源的已知限制另见 [会议审计](venue-audit-2026-10-05.md)。
